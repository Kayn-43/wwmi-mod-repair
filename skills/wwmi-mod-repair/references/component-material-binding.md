# 组件材质绑定与形态切换

适用：已修模型仍在首次显示、切人、变形或下车后服装/身体错色，拉近视角或打开菜单后恢复。历史上补别名改善过，却未覆盖新触发条件时，也检查此分支。先确认实际 Mod 绘制已执行，不能由症状直接判定根因。

## 判断绑定缺口

追踪异常部位的自定义 draw、所在组件、纹理资源与执行条件；身体组件可同时绘制服装，服装也可分属多个组件。作者绘制注释与 DDS atlas 可辅助定位，但不能只凭组件编号判断身体/脸/衣服。

逐项区分：

| 文件事实 | 可能的修复方向 | 不足以证明什么 |
|---|---|---|
| 同一材质低分辨率输入未命中，正常输入可唯一对应资源 | 精确别名，见 texture-streaming.md | 不证明未来所有分辨率均覆盖 |
| 实际组件依赖旧 hash，没有已确认用途的材质引用 | 组件级材质绑定 | 不证明缺少 RabbitFX 就是所有角色的共同根因 |
| 仅在特定 hash 回调中补 Diffuse；组件调用 SetTextures 时未给默认 Diffuse | 有依据的默认 Diffuse，加已知形态覆盖 | 不保证未知形态仍保留专用颜色细节 |
| 设置保存正确，但颜色错 | 独立检查材质分支 | 不应继续修改持久变量或服装选择 |
| 脸部因某项 RabbitFX 注入而错色，取消该项有效 | 保留局部 null 修补与传统 override | 不应按“完整四项材质”强行给脸填图 |

用户只反馈服装异常时，优先核对所属服装组件，不盲目扩到头发、脸与全体组件。

## 取得材质用途证据

作者固定版本配置的 meta 可作为直接来源：D=Diffuse、L=Lightmap、N=Normalmap、M=Materialmap；其他用途按实际实现。记录 commit、配置 SHA256 和本 Mod 的完整 Resource 名，再与本机 RabbitFX 及已有正常帧核对。

本轮使用的 [Wuwa_Mod_Fixer RabbitFxFixer](https://github.com/Moonholder/Wuwa_Mod_Fixer/blob/6fa4d31e6fd2763cd5b8c98f7c387c1c8988a8d0/src-core/src/fixers/rabbit_fx.rs) 与 [配置](https://github.com/Moonholder/Wuwa_Mod_Fixer/blob/6fa4d31e6fd2763cd5b8c98f7c387c1c8988a8d0/config.json) 是历史固定来源；`--stable-texture` 与派生 hash 修补是分开的模式。未来需要最新适配时重新获取，不将此 commit 称为当前最新版。

配置没有 meta 时，结合实际正常帧的输入格式、分类值、shader 匹配、旧 override 赋值及本机 ShaderRegex 替换规则推导。明确标为“推导映射”，保留缺少原始 PS 反汇编等边界；DDS 解码预览只作交叉检查，不把粉/橙色编码图视为坏贴图。无法唯一定位的资源保持未知。

`ResourceTexture33` 与 `ResourceTexture33aa` 必须完整解析。本轮爱弥斯前者是 Normalmap，后者是 Charged Diffuse，截断资源名会选错用途。相同 hash 在不同组件/槽位可能对应不同资源，不能取第一条赋值。

## 在真实绘制分支绑定

保留 `$mod_enabled`、骨骼就绪、remap 和作者 Toggle。已验证结构是在目标组件 `handling = skip` 后、旧纹理检查前设置用途引用并调用本机 `SetTextures`；不把绑定放到全局 Present。

此顺序与上述作者实现一致，本机 SetTextures 要读取输入的材质分类。旧检查先替换输入后，格式/mip 已可能改变，不能未经验证调换顺序。保留原有传统 override，避免将一种通路成功误当成另一通路可以删除。

只提交用途已定位的必要资源；明确缺失或有意禁用的用途可为 null，不为凑齐四项而虚构映射。若组件确实需要 Diffuse，核对它在调用之前已有有效默认引用，或每条实际分支均能提供它；“存在一个 Diffuse hash override”不等于所有输入均能获得 Diffuse。

本轮 RabbitFX 8.3.2 的行为是：

- `SetTextures` 在 `ps == 1718.1` 时才把材质引用传至 t60–65 并设置分类/启用标志；其他 PS 不会因此自动支持。
- 调用结束会清空材质 Resource 引用，不依赖上一角色/上一帧留下的引用。
- 对应 ShaderRegex 的 post `ClearTSR` 清理 t60–65 与标志。核对真实实现与执行覆盖，不添加广域 ShaderOverride 或私有 filter_index 强迫不支持的 pass。

这些数值是本机历史实现，未来必须读实际框架。稳定 Mod 也可能有共享 hash、object_detected 条件及相似清理结构，仅发现它们不能证明跨角色污染或状态泄漏。

## 默认贴图与普通/变形分流

需要多张 Diffuse 时，先实际解码并核对文件/像素；同尺寸、同前缀不代表可互换。优先保留作者已有形态选择与条件。

爱弥斯最终实验的结构是：Component3 先提供已确认的普通 Diffuse 默认值；已识别的 Charged hash 仍在既有组件/槽位/受支持 PS 条件下覆盖 t60。没有新增重复检查、第二次 SetTextures 或持久化“上一次形态”标志。

此方式解决的是“未识别输入时颜色贴图没有默认绑定”的缺口。未知 Charged 输入仍可能使用普通兜底，不能保证专用颜色细节；不得把它变成全部 Mod 统一普通贴图的规则。没有明确普通默认用途时，先保留未知，不自动取第一个资源。

## 实验与复用边界

先在一个映射明确的组件试验，保留已成功版本；有效后再按每个角色自己的证据扩展。莫宁、绯雪、爱弥斯最终改动与用户结果见 [six-mod-casebook.md](six-mod-casebook.md)。同症状可复用方法，不复用资源号、槽位或 hash。

继续使用已有有效帧。若缺少的只是异常部位描述，可询问衣服/皮肤/脸并继续离线研究，不重复要求用户完成整套采集。需要新证据时明确缺少哪一组件、状态或支持的 shader。

下车与大招是触发条件；帧中模型范围、VS/PS 或输入变化分别记录。旧数据既未捕获变形瞬间，也不能独立证明当前补丁错误。“人物建模改变”“显存污染”“初始化延迟”都不能仅由拉近恢复推出。

避免重复本轮失败路径：全组件 12 槽重检查、批量推断低 hash、无角色证据的跨角色 hash 改写、移除骨骼保护或同时改变框架。一个角色的有效帧只能提供共性线索，不能为另外两人背书。

最终按用户反馈分别记录：已改善、相对稳定、效果很好、首帧或过渡完全消失。先核对活动 SHA256，再冻结成功文件；出现新触发失败时保留历史改善，撤销对应过期结论，不继续叠加失败实验。
