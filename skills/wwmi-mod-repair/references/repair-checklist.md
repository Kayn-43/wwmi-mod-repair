# 写入与验证细节

按当前诊断选用相关检查，不为普通修补增加无关审批或固定实验数量。

## 差异与资源

- 按节顺序保留重复 `Constants`/`Present` 与重复键；描述哪些节增加和哪些既有节只是增加命令。
- 资源映射同时记录文件名、override hash、调用组件和赋值条件；同一资源可能被多个组件共享。
- `handling = skip` 而没有自定义 drawindexed 的组件仍可能执行注入；核对本机 RabbitFX 的引用清空、ShaderRegex post 清理，再判断是否状态泄漏。
- 保留 BOM/编码；用于 diff 的换行规范化不能替代原始字节备份。不要“顺手修复”作者署名、Toggle默认值或不相关格式。
- DDS 尺寸/格式与预览只辅助定位。BC压缩、sRGB或通道数据无法解码时记录不支持，不填补未知语义；若使用内存格式别名用于预览，禁止把修改的头部写回原贴图。
- 帧描述区分原生输入与回调后 Mod 资源。回调后的尺寸/格式不是原生输入描述；不要把 BC3_TYPELESS 与 BC3_UNORM 称为完整格式相同，也不能从纹理尺寸变化猜材质用途。
- 组件级绑定还应记录用途证据、默认值及普通/变形分流。回调中有 Diffuse 赋值不证明未知输入也会得到它；有意禁用的脸部材质保持 null，不机械套用服装的完整绑定。

## 临时采集

- 验证异常/正常帧确实含目标组件，记录源日志哈希、绘制数量、shader、索引范围与中断标记。没有角色的帧不能作为正常对照。
- 中文路径下主 Mod 的回调文本可能不完整；必要时用独立 ASCII namespace，在特定 mesh 绘制前后只记录槽位描述。诊断不改模型、贴图或分类值，且只在 frame_analysis 时执行。
- 开采集前备份实际框架配置；完整 Launcher 配置可能含无关账户信息，放私有工作区，不打印、不进入交付包。仅修改需要的 WWMI 采集字段。
- 结束后恢复本次更改并移除已知诊断；Launcher 运行期间若更新其他字段，按字段恢复并比较 JSON，保留这些更新。目标若被未知修改，先检查，不能强制覆盖旧备份。

## 缓冲区

- 验证 Index 格式；R32_UINT按4字节索引读取，不把 resource stride=12 误当成每个索引12字节。
- `drawindexed = count, first_index, base_vertex` 使用的是自定义 Index.buf 范围，不是 match_first_index 的原生范围。
- 多个 Toggle 绘制段需要并集；零长度绘制不代表该组件没有其他绘制。
- min/max连续区间不是精确引用集合，除非已证明两者相等。遇到负/非零 base vertex、稀疏集合或特殊索引格式，按真实引用计算，不沿用例子假设。
- 检查顶点数、stride余数和字节修改边界；证明确实未改主UV、非目标组件或受保护缓冲区。
- INI引用保持 `Meshes/TexCoord.buf` 时，修复文件实际写回这个路径；输出名 `TexCoord_fixed.buf` 只是交付名，不必更改Mod资源路径。

## 部署

- 确认实际路径在用户指定Mod目录内；Windows 写入使用 LiteralPath 与同一套 PowerShell 文件操作。
- 覆盖前记录当前 SHA256 和候选 SHA256；备份以 `.BAK` 等非活动扩展名保存，并检查 WWMI include/exclude 规则。
- 若当前内容已不同于分析基线，先读取后续修改并重新合并，不能强制覆盖未知编辑。
- 多文件先全部备份并核验，重新确认目标未并发变化，再写入。任一失败恢复本轮备份；未知文件仍不覆盖。
- 安装后验证两层：候选与目标一致；目录清单中只有预期目标改变。不要递归移动/重建Mod目录。
- 切换实验不混合失败版本的改动，回退默认恢复本次操作前可用版，而非无意回到已经失效的旧hash。
- 多角色分别维护成功/失败状态。只改仍失败的目标，按完整文件清单保护稳定角色；共用回退脚本应验证其他文件在操作前后不变，不因其他角色已安装新成功版就强行覆盖它们。
- 成功后保存与当前活动文件完全一致的版本，必要时保存配套缓冲区；安装器默认源也要指向成功版本。不同角色的成功文件各自固定，不能让一个公共默认参数回装旧实验。

## 结果记录

记录字段可按需要裁剪：当前版本；实际改动文件；SHA256；备份；实验变量；静态检查；用户反馈；独立运行证据是否存在；未逐项测试范围。

“用户确认问题已解决”与“未独立捕获运行日志”可以同时成立。不要用单一 runtime_validated=false 掩盖明确的用户成功反馈，也不要从一句成功推导出所有场景与Toggle均经过测试。

稳定对照、本轮已修成功、部分改善、未测试实验分开记录。严重橙脸消除不等于脸身体无色差；搭配保存不等于材质稳定；“效果很好”不能改写成全部操作无闪帧。

最终答复先说明已安装什么、是否成功以及下一步测试。成功后交付最终文件与简短报告；若是配套INI/BUF，明确两者要一起恢复。
